## 1. 목표와 비목표

### 목표

이 앱을 인터넷에서 접속 가능한 주소에 올린다. **개인이 실제로 쓰는 도구**가 목적이다.
채용 담당자에게 보여주는 전시물이 아니므로 로그인 벽이 노출되는 것은 문제가 되지 않는다.

호스팅 비용은 **$0**이다.

### 비목표

- 다중 사용자 지원. 비밀번호 하나로 잠긴 단일 사용자 앱이다
- 고가용성·무중단. 잠들었다 깨어나는 것을 허용한다
- 수평 확장. 오히려 **금지한다**(§4)
- KCI(국내 논문). 고정 IP가 필요한데 무료로는 얻을 수 없다(§6)

## 2. 왜 Vercel이 아닌가

사용자가 처음 지목한 곳은 Vercel이었다. 실제로 문서를 확인한 결과 이 앱과 맞지 않는다.

> "Vercel deployments don't have a fixed IP address by default."
> Static IPs는 **Pro/Enterprise 전용, 프로젝트당 월 $100.** Hobby에는 없다.

> "Stateless containers, state lives in backing services."
> 파일시스템은 휘발성이고, "instances come and go with traffic"이라 **메모리 상태를 요청 간에 유지할 수 없다.** 영구 디스크·볼륨 미지원.

이 앱이 프로세스 메모리와 로컬 파일에 들고 있는 것은 다음과 같다.

| 무엇 | 어디에 | Vercel에서 |
|---|---|---|
| 세션 (`lib/session.js`의 `new Map()`) | 프로세스 메모리 | 인스턴스가 바뀌면 로그인이 임의로 풀린다 |
| 확인 토큰 (`createTtlCache`) | 프로세스 메모리 | 견적 낸 인스턴스와 분석 인스턴스가 다르면 `428` |
| 예산 상태 (`.budget.json`) | 로컬 파일 | 파일이 사라진다 |
| rate limit (MemoryStore) | 프로세스 메모리 | 인스턴스마다 따로 세어 실효 한도가 몇 배 |
| 분석 캐시·회로차단기·세마포어 | 프로세스 메모리 | 효과 없음 |

**확인 토큰이 "덜 안전해지는" 것이 아니라 오작동한다는 점이 결정적이다.** 사용자가 승인 버튼을 눌러도 무작위로 `428`이 뜬다. 비용 방어가 정상 요청을 막는 방향으로 고장 난다.

Vercel을 쓰려면 세션·확인 토큰·예산·rate limit을 전부 외부 저장소로 옮겨야 한다. 그것은 Phase 2b에 맞먹는 재작업이고, 그러고도 KCI는 여전히 불가능하다.

## 3. 플랫폼 선택 — Render 무료

확인한 조건이다.

| 항목 | Render 무료 |
|---|---|
| 요금 | $0 |
| 도메인 | `*.onrender.com` + HTTPS 자동 |
| 오토스케일링 | **Pro 이상.** 무료에서는 인스턴스가 늘지 않는다 |
| 파일시스템 | 휘발성. 영구 디스크는 유료 전용 |
| 유휴 처리 | 15분 무트래픽 시 정지, 재시작 약 1분 |
| 월 한도 | 750 instance-hours |

**오토스케일링이 유료 기능이라는 점이 이 선택의 근거다.** 인스턴스가 하나로 유지되면 세션·확인 토큰·캐시·회로차단기가 전부 정상 동작한다. Vercel과 갈리는 지점이 여기다.

### 검토했으나 택하지 않은 것

**Fly.io** — 볼륨($0.15/GB·월)과 전용 IPv4($2/월)가 있어 예산 영속화와 KCI를 동시에 풀 수 있다.
다만 무료 티어가 없어져 항상 켜진 소형 머신이 월 $2~3이다. 비용 $0 조건에 맞지 않는다.
**예산 영속화나 KCI가 실제로 필요해지면 이곳으로 옮긴다.**

**외부 저장소(Upstash Redis 등)로 예산 이전** — 무료 호스팅에서도 예산이 영속한다.
그러나 코드 변경과 외부 의존성이 늘어난다. §5의 이유로 지금은 필요하지 않다.

**Render 무료 + 외부 cron 핑** — 콜드스타트를 없애지만 월 730시간을 써서 750 한도에 붙는다.
1분 기다리는 비용이 한도를 태울 만큼 크지 않다.

## 4. 인스턴스는 하나여야 한다

이것은 무료 티어라서 생긴 우연한 성질이 아니라 **지켜야 할 설계 제약**이다.

인스턴스를 늘리는 순간 세션·확인 토큰·rate limit·회로차단기가 인스턴스별로 갈라져
§2에 적은 Vercel의 문제가 그대로 재현된다. Render는 수동 확장을 모든 요금제에서 허용하므로
**실수로 늘릴 수 있다.**

→ `render.yaml`과 `docs/architecture.md`에 이 제약과 이유를 명시한다.
→ 나중에 확장이 필요해지면 그때는 상태를 외부로 옮기는 작업이 선행되어야 한다.

## 5. 예산 파일은 휘발한다 — 그리고 그래도 된다

`.budget.json`은 로컬 파일이므로 정지·재배포마다 사라진다. 하루 50회·월 $5 카운터가 0으로 돌아간다.

이것을 받아들이는 근거는 두 가지다.

**첫째, 1차 방어선은 OpenAI 계정의 지출 한도다.** `docs/SESSION-HANDOFF.md`에 이미 이렇게 적혀 있다.

> 앱 예산은 2차 방어선이다: 자동 충전 차단은 OpenAI 계정 Billing 설정에서 해야 한다.
> 앱은 자기 호출만 막을 수 있다.

계정 쪽에 상한이 걸려 있으면 앱 예산이 리셋돼도 실제 지출은 그 선에서 멈춘다.

**둘째, 이 앱은 비밀번호로 잠긴 단일 사용자 앱이다.** 예산을 소진시킬 수 있는 사람은 본인뿐이다.
공개 API였다면 전혀 다른 판단이 필요하다.

### 결정: `BUDGET_FILE`을 기본값으로 유지한다

비우면 영속화를 아예 하지 않는다(`lib/budget.js`의 `if (!filePath) return;`).
유지하면 **한 세션 안에서는** 하루 50회 한도가 실제로 작동한다. 없는 것보다 낫다.

대신 문서에 "재시작 시 리셋됨"을 분명히 적어 그 숫자를 과신하지 않게 한다.

화면 문구는 바꾸지 않는다. "오늘 N/50회 사용"은 이 인스턴스의 실제 사용량이므로 거짓이 아니다.

---

## 6. KCI는 이번 범위에서 제외한다

KCI OpenAPI는 등록된 공인 IP에서 온 요청만 받는다. Render 무료는 고정 아웃바운드 IP를 주지 않는다.

따라서 `KCI_API_KEY`를 **비워 둔다.** 이 상태에서 앱은 정상 동작하고,
한국어 검색어의 논문 결과만 사유와 함께 비어 나간다(Phase 2b에서 그렇게 설계했다).

사용자가 KCI를 "있으면 좋고 없어도 무방"으로 판단했으므로 이번에는 포기한다.
나중에 필요해지면 Fly.io 전용 IPv4($2/월)로 푼다.

## 7. 배포 정의

`render.yaml`을 저장소에 둔다. 대시보드 클릭 설정은 재현되지 않고 기록도 남지 않는다.

```yaml
services:
  - type: web
    name: eco-si-news-analyze
    runtime: node
    plan: free
    # 인스턴스는 하나여야 한다. 늘리면 세션·확인 토큰이 갈라진다 (설계 §4).
    numInstances: 1
    buildCommand: npm ci --include=dev && npm run build:client
    # ↑ --include=dev 를 지우지 말 것. vite가 client의 devDependency라
    #   NODE_ENV=production 이면 설치가 건너뛰어져 빌드가 깨진다 (설계 §8).
    startCommand: npm start
    envVars:
      - key: NODE_ENV
        value: production
      - key: TRUST_PROXY
        value: "true"
      - key: KCI_API_KEY
        value: ""
      - key: MY_SECRET_PASSWORD
        sync: false          # 대시보드에서 입력한다. 저장소에 넣지 않는다.
      - key: OPENAI_API_KEY
        sync: false
```

**확인되지 않은 것이 둘 있다.** 구현 단계에서 실제로 시도하고 결과를 문서에 남긴다.

1. **Blueprint가 무료 플랜에서 동작하는지** — Render 문서에 명시돼 있지 않다
2. **`numInstances`를 무료 플랜에서 설정할 수 있는지** — 무료는 확장을 지원하지 않으므로 이 필드가 거부될 수 있다

둘 중 하나라도 안 되면 같은 값을 대시보드에 직접 넣는다. 어느 쪽이든 이 파일이 설정 기록 역할을 한다.
`numInstances`가 거부되면 **인스턴스 1개 제약은 코드가 아니라 문서와 규율로만 지켜진다** —
§4를 `docs/architecture.md`에 남기는 이유가 그래서다.

### 환경변수

| 변수 | 값 | 이유 |
|---|---|---|
| `NODE_ENV` | `production` | 세션 쿠키에 `Secure`가 붙는다. Render가 HTTPS를 준다 |
| `TRUST_PROXY` | `true` | 켜지 않으면 `req.ip`가 프록시 주소가 되어 rate limit이 전체를 한 통으로 센다 |
| `MY_SECRET_PASSWORD` | 대시보드 입력 | 공개 인터넷이므로 로컬보다 길게 |
| `OPENAI_API_KEY` | 대시보드 입력 | |
| `KCI_API_KEY` | 빈 값 | §6 |
| `PORT` | 설정하지 않음 | Render가 주입하고 `config.port`가 읽는다 |
| 나머지 | 기본값 | `.env.example`과 같다 |

`app.listen(config.port)`는 호스트를 지정하지 않아 `0.0.0.0`에 바인딩된다. 수정할 것이 없다.

## 8. 빌드가 깨지는 함정

`vite`와 `@vitejs/plugin-react`는 **`client/`의 devDependencies**다.
그런데 `NODE_ENV=production`은 빌드 단계에도 적용되고, 그러면 `npm ci`가 devDependencies를 건너뛴다.

결과는 `vite: not found`다. `client/dist`가 `.gitignore`에 있어 미리 만들어 둔 산출물도 없다.

→ 빌드 명령에 **`--include=dev`를 반드시 넣는다.**

이것을 `render.yaml`에 주석으로 남긴다. 나중에 누군가 "production 빌드에 devDependencies가 왜 필요하지"라며 지울 수 있다.

### Node 버전을 고정한다

`package.json`에 `engines`가 없어 플랫폼이 임의로 고른다. 어느 날 조용히 바뀔 수 있다.

```json
"engines": { "node": ">=22" }
```

로컬은 Node 24.18.0이다. 이 앱은 Node 24 전용 기능을 쓰지 않으므로 22 이상이면 동작한다.
구현 단계에서 배포된 실제 버전을 로그로 확인한다.

## 9. 검증

배포 후 순서대로 확인한다. `verify-research.sh`와 `verify.sh`는 이미 `BASE_URL`을 인자로 받으므로
스크립트를 고칠 필요가 없다.

| 순서 | 명령 | 기대 | 비용 |
|---|---|---|---|
| 1 | `curl <URL>/api/health` | `llmMode: live` | 0 |
| 2 | `./scripts/verify-research.sh <URL>` | 통과 14 / 실패 0 | 0 |
| 3 | `MY_SECRET_PASSWORD=<값> ./scripts/verify.sh <URL>` | 통과 9 / 실패 0, `degraded=false` | 약 $0.005 |
| 4 | 브라우저 | 로그인 → 수집 → 승인 → 보고서 | 실행 시 약 $0.005 |

2번은 Phase 2b가 병합된 뒤에야 14항목이 된다. 병합 전이라면 Phase 2a 기준으로 통과하면 된다.

**콜드스타트 때문에 첫 요청이 약 1분 걸린다.** 스크립트가 타임아웃으로 실패하면 결함이 아니라
정지 상태였던 것이므로, 검증 전에 한 번 깨워 두고 시작한다.

## 10. 알려진 한계 — 문서에 남길 것

1. **예산 파일이 휘발한다.** 정지·재배포마다 카운터가 0으로 돌아간다. 1차 방어선은 OpenAI 계정 한도다
2. **15분 유휴 후 정지한다.** 다시 깨우는 데 약 1분
3. **KCI를 쓸 수 없다.** 아웃바운드 IP가 유동이다
4. **월 750 instance-hours.** 계속 깨워 두면 한도에 붙는다
5. **인스턴스를 늘리면 안 된다.** 상태가 갈라진다(§4)
6. **단일 사용자 앱이다.** 비밀번호 하나가 유일한 인증이고, 공개 인터넷에 노출된다

---

## 11. 하지 않는 것

- **Dockerfile** — Render가 Node를 그대로 빌드한다. 다른 플랫폼으로 옮길 때 만든다
- **외부 cron 핑** — 750시간을 태울 이유가 없다
- **예산 외부 저장소** — 계정 한도가 1차 방어선이면 불필요하다
- **UI 문구 추가** — 화면의 수치는 이 인스턴스의 실제 사용량이라 거짓이 아니다
- **CORS 설정** — 동일 출처라 지금도 미사용이다
