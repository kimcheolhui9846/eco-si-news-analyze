# 구현 계획과 설계 판단 기록

원본 요구사항(`claude-code-integrated-prompt.md`) §1–5가 요구하는 기술 계획 기록이다.
무엇을 만들었고, 관점이 충돌했을 때 무엇을 근거로 어느 쪽을 골랐는지 남긴다.

- **작성일**: 2026-09-02
- **현재 단계**: Phase 1 완료

## 1. 범위 분할

원본 요구사항은 서로 독립적인 서브시스템 네 개를 한 문서에 담고 있었다. 통째로 진행하면 어느 것도 충분히 검증되지 않은 채 "완료"로 보고될 위험이 컸다 — 원본 §1-7이 금지하는 바로 그 상황이다.

| 단계 | 범위 | 상태 |
|---|---|---|
| **Phase 1** | 인증·세션, API 비용 방어, `/api/analyze/news` 분석 엔진, 예산 통제, 테스트, 문서 | ✅ 완료 |
| Phase 2 | 데이터 커넥터 5종 + `/api/research` 오케스트레이션 | 미착수 |
| Phase 3 | React 프론트엔드 12개 컴포넌트 | 미착수 |

각 단계는 그 자체로 실행·검증 가능한 완성품이어야 한다는 원칙을 따랐다.

### Phase 1에서 의도적으로 제외한 것

- NewsProvider / FinancialDataProvider / ResearchPaperProvider / ExperimentDataProvider / MarketChartProvider
- React 프론트엔드

## 2. 관점별 검토 결론

### 백엔드·API 아키텍처

`server.js` 단일 파일에 핵심 로직을 담되 `createApp` 팩토리로 감쌌다. 직접 실행될 때만 `listen`한다. 파일은 섹션 주석으로 구획했고, Phase 2에서 provider가 붙을 때 `lib/`로 분리한다.

주입 대상은 `clock`, `llm`, `env` 셋으로 제한했다. 그 이상은 테스트 편의를 위한 과도한 추상화라고 판단했다.

### 보안·인증·비용 방어

방어를 **미들웨어 등록 순서**로 구조화했다: IP 한도 → 본문 크기 → 인증 → 세션 한도 → 검증. 인증을 통과하지 못한 요청이 LLM 호출 코드에 도달할 수 없다는 것을 코드 배치로 보장하고, 테스트에서 mock 호출 카운터로 확인한다.

원본 §7의 25개 항목을 모두 구현했으며 전부 환경변수로 조정 가능하다.

### 데이터 수집·출처 신뢰성

Phase 1은 수집하지 않으므로 **출처 무결성**에 집중했다. 핵심 판단은 "LLM에게 출처를 맡기지 않는다"이다 (§3.2 참조).

### LLM·RAG 프롬프트·환각 방지

프롬프트 지시를 신뢰하지 않고 결정적 후처리로 강제하는 방향을 택했다. 시스템 프롬프트로 "URL을 만들지 말라"고 지시하되, 실제 보장은 응답 후 화이트리스트 대조가 한다.

### 금융 데이터·차트 처리

Phase 1에서는 `marketData`를 검증·정규화해 프롬프트에 싣는 데까지만 한다. 시장 데이터가 없으면 침묵하지 않고 명시적으로 "자료 부족"이라고 프롬프트에 적는다 — 빈칸으로 두면 모델이 추측으로 메우기 때문이다.

투자 권유가 되지 않도록 시스템 프롬프트에서 확정적 예측·매매 권유를 금지하고, 응답 스키마가 시나리오별 **무효화 조건**을 필수로 요구하게 했다.

### UI/UX·접근성

Phase 3 과제. Phase 1은 `meta.degraded` 같은 필드로 프론트엔드가 품질 저하를 표시할 수 있게 준비했다.

### 테스트·배포

`node:test` + `supertest`. **실제 API 키 없이 164개 테스트가 전부 통과**한다. 시계 주입으로 세션 만료를, mock LLM으로 상류 장애를 재현한다.

## 3. 관점이 충돌한 지점과 해결

### 3.1 단일 파일 요구 vs 테스트 용이성

**충돌**: 원본 §3은 "실행 가능한 하나의 `server.js`"를 요구한다. 그러나 테스트가 실제 포트를 열거나 세션 만료를 15분 기다릴 수는 없다.

**해결**: 팩토리 + 조건부 `listen`.

```js
export function createApp({ env, clock, llm, extraRoutes }) { ... }

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  createApp().app.listen(port);
}
```

단일 파일 요구를 지키면서 테스트가 포트 없이 앱을 만들고 시간을 조작할 수 있다. 두 요구를 모두 만족한다.

### 3.2 `sources`를 LLM에게 맡길 것인가

**충돌**: 원본 §13의 권장 응답 구조에는 `sources` 필드가 있다. 그대로 따르면 LLM이 출처 목록을 작성한다. 그러나 원본 §10·§15는 "존재하지 않는 URL을 생성하지 말 것"을 요구한다. 모델이 쓰게 두면 이 요구를 프롬프트로만 지탱하게 된다.

**해결**: `sources`를 LLM 응답 스키마에서 **제거**하고 서버가 입력 자료에서 직접 생성한다. 응답에는 `sources`가 그대로 나가므로 **사용자가 받는 것은 달라지지 않는다.** 다만 모델이 관여할 경로가 없으므로 위조가 구조적으로 불가능해진다.

추가로 보고서 본문의 URL도 화이트리스트로 후처리해 입력에 없던 것을 제거하고 `meta.fabricatedUrlsRemoved`에 집계한다.

**근거**: 프롬프트는 확률적이고 후처리는 결정적이다. 보장이 필요한 곳에는 결정적 수단을 쓴다.

### 3.3 캐시 히트 시 세션을 연장할 것인가

**충돌**: 원본 §6.4는 세션 연장 조건에 "OpenAI 분석 성공"을 포함한다. 그런데 캐시 히트는 OpenAI를 호출하지 않는다. 문자 그대로 읽으면 연장하지 않아야 한다.

**해결**: **연장한다.** 캐시 히트는 사용자가 정상적으로 서비스를 사용한 것이고, 응답도 `200`이다. 캐시가 잘 맞을수록 세션이 빨리 끊기는 것은 사용자에게 벌을 주는 셈이다.

원본의 의도는 "미들웨어를 통과만 해도 연장되는 것"을 막는 데 있다고 판단했다. 그 의도는 그대로 지켜진다 — 연장은 `200`을 내보내기 직전 한 곳에서만 일어난다.

### 3.4 `marketData`를 필수로 할 것인가

**충돌**: 원본 §11의 요청 예시에는 `marketData`가 있고 "객체여야 한다"고 검증을 요구하지만, 필수인지는 명시하지 않았다.

**해결**: **선택**으로 두되 있으면 형식을 엄격히 검증한다. 뉴스만으로도 분석이 성립하고, 원본 §8의 "원하는 데이터 범위" 항목이 뉴스만 선택하는 경우를 상정하고 있기 때문이다.

없으면 프롬프트에 "자료 부족 — 시장 데이터가 제공되지 않았습니다"라고 명시해 모델이 추측하지 못하게 한다.

### 3.5 인증 실패에 401인가 403인가

**충돌**: HTTP 표준상 자격증명 누락·무효는 `401 Unauthorized`가 맞다. `403 Forbidden`은 인증은 됐으나 권한이 없을 때다. 원본 §6.2와 §18은 `403`을 명시한다.

**해결**: **원본대로 `403`.** 표준에서 벗어나지만 사용자 요구사항이 명시적이고, 테스트 요구사항도 `403`을 검증하도록 되어 있다. 전 경로에서 일관되게 `403`을 쓴다.

### 3.6 호출 한도를 무엇으로 셀 것인가

**충돌**: 사용자가 "한도를 정하고 원할 때 호출"을 요청하며 일일 호출 수를 골랐다. 그러나 이어서 밝힌 목적은 **"추가 크레딧 자동 결제 방지, 비용이 한정적"**이었다. 호출 수와 지출액은 비례하지 않는다 — 기사 20개짜리와 1개짜리의 비용 차이가 크다.

**해결**: 사용자가 고른 일일 호출 수를 유지하되 **월 누적 비용(USD) 상한을 함께** 넣고, 실질적 상한은 비용 쪽이 담당하게 했다. 둘 중 먼저 닿는 쪽에서 차단한다.

또한 예산 상태를 **파일에 영속화**했다. 메모리에만 두면 서버 재시작이 곧 예산 리셋이 되어 "비용 상한"이라는 목적 자체가 무너진다.

**사용자에게 명확히 전달한 한계**: 앱 예산은 이 앱의 호출만 막는다. 자동 충전 차단은 OpenAI 계정 Billing 설정에서 해야 하며, 그것이 1차 방어선이다.

### 3.7 "원할 때 호출"을 어떻게 강제할 것인가

**문제**: 단순히 예산만 두면 실수로 큰 요청을 눌렀을 때 이미 돈이 나간 뒤다.

**해결**: 비용이 드는 호출을 2단계로 나눴다.

1. `POST /api/analyze/estimate` — LLM을 호출하지 않고 예상 비용·남은 예산·확인 토큰을 반환
2. `POST /api/analyze/news` — `X-Confirm-Token` 헤더 필수

확인 토큰은 **세션과 요청 내용에 묶인 일회용**이다. 작은 요청으로 견적을 받고 큰 요청을 실행하는 우회를 막기 위해 `cacheKey`(정규화된 자료의 해시)로 대조한다.

두 엔드포인트가 `prepare()` 함수를 공유하므로 견적과 실행이 다른 계산을 할 수 없다.

**예외**: 캐시 히트는 LLM을 부르지 않아 비용이 0이므로 확인도 예산 차감도 요구하지 않는다. 무료인 동작에 승인을 요구할 이유가 없다.

| git이 `server.js`를 바이너리로 취급 | 정규식에 리터럴 제어문자를 삽입 | ` ` 형식 이스케이프로 교체하고, 이미 만들어진 커밋 2개를 재작성 |

## 7. Phase 2a 설계 판단

### 7.1 검색이 되는 소스에는 본문이 없다

설계 전에 후보 소스를 실제로 호출해 확인했다. 그 결과가 구조를 결정했다.

| 소스 | 검색 | 본문 |
|---|---|---|
| Google News RSS | ✅ | **0자** (제목 반복 앵커뿐) |
| 연합뉴스 RSS | ❌ 최신 피드만 | 83자 |
| 전자신문 RSS | ❌ 최신 피드만 | 250자 |
| 한국경제 RSS | ❌ | 0자 |

둘 중 하나만 쓰면 커버리지나 분석 깊이를 잃는다.

**해결**: 하나의 provider가 피드 레지스트리를 소비하고, `kind`가 `search`면 검색어를 URL에 넣고 `topic`이면 피드를 받아 키워드로 거른다. 코드 경로는 하나이고 차이는 설정에 있다.

**한계를 숨기지 않는다**: 각 자료에 `contentKind`를 붙여 프롬프트에 싣고, 시스템 프롬프트가 제목만 있는 자료로 본문을 추론하는 것을 금지한다. 응답의 `headlineOnlyCount`로 사용자도 분석 깊이의 한계를 미리 안다.

### 7.2 크롤링을 하지 않기로 한 이유

전문을 얻으려면 언론사 페이지를 긁어야 하는데, SSRF 표면·사이트별 파싱·약관 문제가 한꺼번에 딸려온다. **RSS 링크를 fetch하지 않는 것**이 지금 SSRF를 막는 실질적 근거다.

### 7.3 한글 티커 해석은 사전으로만 가능하다

Yahoo 검색이 한글 질의에 `400`을 반환하는 것이 확인됐다. LLM으로 의도를 파싱하면 분석 1회당 호출이 2회가 되어 사용자의 비용 제약과 충돌한다. 내장 별칭 사전이 유일한 경로다.

### 7.4 차트 해석을 LLM에게 맡기지 않는다

이동평균·등락률·변동성을 코드가 계산하고 사실만 서술하는 문장으로 조립한다. LLM에게 맡기면 없는 추세를 지어낸다. Phase 1이 출처 URL을 후처리로 강제한 것과 같은 원칙이다.

### 7.5 수집과 분석을 분리한 이유

수집은 LLM을 부르지 않아 무료다. 별도 엔드포인트로 두면 사용자가 무엇이 수집됐는지 보고 돈을 쓸지 정할 수 있다. 견적과 확인 토큰을 수집 응답에 함께 실어 왕복은 2회로 유지한다.

이 구조가 성립하려면 정규화가 멱등이어야 한다 — `collect`와 `analyze`가 같은 `cacheKey`를 계산해야 확인 토큰이 통한다. 테스트로 고정했다.

## 8. Phase 2a 구현 중 발견해 고친 것

실네트워크 검증에서만 드러난 결함들이다. 픽스처 테스트로는 잡히지 않았다.

| 문제 | 원인 | 조치 |
|---|---|---|
| 제목에 매체명 접미사가 남음 (`"삼성전자 - 매일경제 마켓"`) | 접미사 제거 정규식이 도메인 형태(`v.daum.net`)만 처리 | `source` 요소의 값으로 정확히 제거. 제목 중간의 `" - "`는 건드리지 않는다 |
| 현재가와 추세 문장의 종가가 모순 (224.41 vs 217.44) | 전자는 장중 호가, 후자는 마지막 일봉 종가 | 두 값이 다르면 왜 다른지 추세 문장이 직접 설명 |
| 수집 실패 시 원인을 알 수 없음 | `COLLECTION_FAILED`를 던지며 `degraded`를 버림 | 던지기 전에 `degraded`·`feedsUsed`를 로그에 남김 |

`server.js` 분리에서도 두 가지가 걸렸다. `safeCompare`가 `function` 선언이라 export가 없었고, 로그인 스키마가 `zod`를 참조해 `server.js`에 import가 필요했다. 둘 다 164개 테스트가 즉시 잡아냈다 — **순수 이동을 테스트 통과로 검증한다는 방식이 실제로 작동했다.**

### 진단 과정에서 겪은 함정

수집이 계속 `COLLECTION_FAILED`로 실패해 provider를 의심했으나, 단독 실행에서는 정상이었다. 원인은 **Git Bash 콘솔에서 curl에 한글을 직접 넣어 인코딩이 깨진 것**이었다. UTF-8 파일로 써서 `--data-binary`로 보내니 즉시 통과했다. `scripts/verify-research.sh`는 이 방식을 쓴다.
